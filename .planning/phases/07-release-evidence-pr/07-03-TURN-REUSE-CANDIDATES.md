## Minimal integration seam

The existing `createTurnModelRecorder.acquire(game, proposal)` already brackets
the actual coordinator factory call. Add an optional recorder argument only to
the three fixture factories above and select that path in the named tests.
Use `RelayCoordinator`/`RaceCoordinator` from each suite's existing loaded module
graph. Keep Game construction and pre-acquisition terrain arrangement unchanged;
do not claim earlier imports or arrangements as acquisition coverage.

Wrap the existing action blocks in synchronous `recorder.interval` calls, with
all original assertions retained. Place later wallet/offer/terrain fixture edits
between intervals. A small shared test adapter can read optional configuration,
create recorders and collect sidecars. At the suite's final `after`, independently
capture the complete Node parent's payload and combine recorded intervals only.
The last selected lifetime's payload is not the final parent: unrelated tests
may execute after it and remain globally accountable without mode attribution.

Register selected lifetime counts and exact phase pairs on the existing whole
jobs. No test filtering or duplicate assertion file is required. A runtime-only
`bind` API would require validator/provenance changes because existing validation
requires a real acquiring interval per lifetime; inventing acquisition after
construction is forbidden. The existing factory seam avoids that expansion.

The recorder verifies coordinator class, session/host/composition identity,
actual base and stable setup. It does not establish arbitrary custom definition
contents; only these inspected, unchanged Game/coordinator constructors supply
the intended modes. This integration must not broaden applicability authority
or accept arbitrary user-supplied definitions as canonical mode evidence.
