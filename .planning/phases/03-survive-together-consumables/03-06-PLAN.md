<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Visible UI owner/action → session dispatcher | Pointer, keyboard, or controller focus can become stale or attributed to the wrong player. |
| Authoritative session → UI projection | UI must not invent recovery eligibility, charges, success, results, or lifecycle transitions. |
| Built iframe → host/runtime | Theme, mute, size, and input arrive through the established napplet/runtime surface. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-06-01 | Spoofing | owner/target UI action | high | mitigate | Bind visible owner plus action/context version, clear focus/latches on owner/state changes, and let authoritative handler revalidate before commit. |
| T-03-06-02 | Tampering | optimistic recovery/result UI | high | mitigate | Render counts, positions, protection, notices, and results only from committed session snapshots; invalid actions retain prior state. |
| T-03-06-03 | Denial of service | all-dead settlement | high | mitigate | Consume mode-owned terminal predicate so only a valid pending offer delays immutable settlement; ghosts/unused charges cannot. |
| T-03-06-04 | Information disclosure | local participant labels/stats | low | accept | Labels and run statistics are intentionally visible to players sharing the local screen and contain no remote secrets. |
| T-03-SC | Tampering | package installs | high | mitigate | No dependency or package-manager install is allowed in this plan. |
</threat_model>
