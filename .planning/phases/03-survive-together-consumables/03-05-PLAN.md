## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Controller attribution → market owner | Input focus and seat/device identity select a wallet and inventory to mutate. |
| Market request → wallet/inventory commit | Price, funds, capacity, offer, owner, and lifecycle can change before mutation. |
| Player modifiers → shared world | Multiple private inventories contribute to one deterministic simulation projection. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-05-01 | Spoofing | owner-attributed market actions | high | mitigate | Resolve live owner from Phase 2 attribution and verify participant/seat, owner version, lifecycle, and context at commit. |
| T-03-05-02 | Tampering | wallet debit plus inventory credit | high | mitigate | Immutable transaction plan, exact price/capacity checks, atomic versioned commit, and duplicate/replay tests prevent partial or repeated mutation. |
| T-03-05-03 | Elevation of privilege | shared-world card resolver | medium | mitigate | Exhaustive descriptors, active-only contributors, one best value, stable tie rule, and owner-local projections prevent cross-player stacking/leakage. |
| T-03-05-04 | Repudiation | market response state | low | mitigate | Return owner/context/version with outcomes so browser tests can attribute each change deterministically. |
| T-03-SC | Tampering | package installs | high | mitigate | No dependency or package-manager install is allowed in this plan. |
</threat_model>
