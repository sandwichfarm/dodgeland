## Feasibility and state coverage

The proposed geometry is internally coherent and measurable. At320×560,144+112 leaves304px; at1000×280,80+112 leaves88px; at900×600,160+112 leaves328px; at2400×1200,416+128 leaves656px. The240×240 rule reserves80px and allows bounded compact pages for the remaining160px. These are maximum occupied bands/minimum scene bounds, not proof that implementation currently meets them. Height precedence and the wide-but-short fallback prevent tall cards appearing merely because width increases.

The optional generic presentation-safe viewport is conditional on retained CSS-only failure evidence. It defaults to exact solo projection, preserves authoritative camera anchor/world coordinates/fog/clocks, and transforms all scene layers and edge cues consistently. The prohibition on hiding otherwise visible nearby travelers prevents a false pass from cropping actors. Full voxel/hop/interpolation and packed identity/status envelopes are compared with actual DOM occluders, including shelves, toasts and shadows; neither exposed area nor label-only tests qualify. The contract requires real initial/lateral900×600 journeys with four Survive Arcade/Flow/Race seats and only the actual active Relay runner. This is an implementable measurement contract, not permission to invent Relay actors or move world positions.

G2 clearly scopes suppression to duplicate solo personal presentation and accessibility content, preserves shared per-seat facts and the owned hand, keeps global controls, and restores solo chrome on cancellation/retry. The shared wallet must come from the selected owner rather than relabelling `game.run.wallet`. Existing owner-context invalidation, one physical hand/market tree and paid-pack/page continuity remain explicit.

Zero/one/many cases are substantively covered by inherited states and the new contract: zero eligible items/targets have copy and safe return; zero available players uses waiting/reclaim or existing terminal policy; Relay has one live actor with original roster identities retained; simultaneous modes retain2–4 seats and explicit dead/ghost/finished statuses; results enumerate frozen participant records, including archived/replaced identities, rather than current avatars. Partial/disconnected state cannot acquire fresh authority or appear as death. Unavailable optional controllers keep keyboard/pointer usable. Missing backend data or network-loading states are not invented for this local game.

Overflow is addressed through bounded detail/result pages and complete accessible text, not hidden required facts. Resize retains participant/logical page/action and restores focus to an existing summary or safe scene. Notice→restore preserves offers/targets/handoff and pause reason without activation. Focused keyboard/controller activation, wrong-seat restrictions, terminal browsing and held-input seeding are preserved. Full details remain accessible after summaries replace tall cards; pending recovery is a labelled action or actionable affected-seat summary, never only a decorative badge.

Existing result semantics are preserved: non-ranked equal-height Survive team, Relay contribution ties and leg ledger, Race true competitive ties and explicit unranked DNF. No mechanics, dependency, input authority, result accounting or optional-domain expansion is introduced.

## Recommendation — non-blocking

**Dimension2, compact summary wording:** Under Required information, “Every live summary shows” identity/health/lifecycle could be read as applying to every44px marker chip, while the frame table explicitly uses a marker strip plus the selected seat's summary. Add a short clarification that compact/short nonselected chips retain identity plus accessible current health/lifecycle and an announced actionable recovery indication, while the selected visible summary shows the full required concise facts. Regular/wide summaries continue showing each seat's visible health/lifecycle. The explicit tier rules and retained inspection flow make the current design implementable; this clarification prevents inconsistent execution without reopening the approved compact pattern.
