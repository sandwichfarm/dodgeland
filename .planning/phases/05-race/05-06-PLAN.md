<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Authoritative Race state → DOM/canvas/audio | Presentation must not invent state or become simulation authority. |
| Visible owner/input → transaction | Displayed owner, invoking device, and stale context can diverge. |
| Injected controller transport → app | Optional runtime snapshots remain shell-owned and untrusted. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-21 | Spoofing | owner/target actions | high | mitigate | Seat + lifecycle/context generation on every request, synchronous invalidation, and crossed-input browser tests. |
| T-05-22 | Tampering | render-derived authority | high | mitigate | Renderer/UI consume immutable views only; model tests compare authoritative state before/after visuals. |
| T-05-23 | Elevation of Privilege | controller/browser APIs | high | mitigate | Authorized injected adapter only, no native polling/direct network/storage/host DOM, and no-domain fallback. |
| T-05-24 | Information Disclosure | stale owner tree | medium | mitigate | One DOM tree and complete transient/focus/input reset before another owner renders. |
| T-05-25 | Denial of Service | audio/motion feedback | low | accept | Existing mute/motion preferences plus static/text alternatives keep gameplay usable; device-muted automation verifies graph safely. |
| T-05-SC | Tampering | package installs | high | mitigate | No install; lockfile gate. |
</threat_model>
