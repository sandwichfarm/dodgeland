<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Compile-time definition input → rule composer | Author-supplied objects become engine policy only after validation and normalization. |
| Immutable rules → Game/Renderer | Validated policy controls simulation and presentation without identity-based branches. |
| Active Game → development reconstruction | A replacement run receives an already validated definition without acquiring new runtime authority. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-05 | Tampering | nested mode input | high | mitigate | Clone and recursively freeze every group; test mutation of original and composed nested values. |
| T-01-06 | Denial of Service | numeric rule values | high | mitigate | Reject non-finite, non-positive, unbounded, and incompatible values before Game construction. |
| T-01-07 | Elevation of Privilege | lifecycle handlers | medium | mitigate | Definitions are compile-time local code only; expose bounded existing solo event contexts and no shell/network/storage authority. |
| T-01-08 | Repudiation | legacy compatibility | medium | mitigate | Keep named compatibility tests and require the pinned differential gate after each task. |
| T-01-17 | Tampering | development reconstruction | medium | mitigate | Pass the current frozen definition explicitly on jumps and test custom/default behavior through the real reconstruction API. |
| T-01-SC | Tampering | package supply chain | low | accept | No package-manager install or lockfile edit occurs in this plan. |
</threat_model>
